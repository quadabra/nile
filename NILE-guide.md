# NILE — Nested Interface Layout Engine

**NILE** — Angular-проект (библиотека/приложение) для создания тайлинговых интерфейсов в браузере в стиле scrollable tiling.

## Структура интерфейса

- **Desktop** (рабочий стол) — один потенциально бесконечный горизонтальный скролл **колонок**.
- Внутри каждой колонки — вертикальный стек **тайлов** (панелей/компонентов).
- **Контейнер десктопов** — вертикальная структура с нумерованными/именованными десктопами (переключение между ними).

Основная идея: несколько именованных десктопов, каждый из которых представляет собой niri-подобный горизонтальный тайлинг.

## Цели проекта

Проект отвечает за:

- Обёртку интерфейса (контейнер десктопов + контейнер колонок внутри десктопа)
- Создание тайлов (динамическое подключение Angular-компонентов)
- Расположение и изменение размеров
- Перемещение тайлов между колонками и внутри колонок
- Удаление тайлов и колонок
- Управление десктопами (создание, переименование, переключение, удаление)
- Сохранение и восстановление состояния (сериализация)

**Не является целью на старте**: вынос в отдельную библиотеку для других фреймворков, готовые UI-компоненты контента, сложные анимации «из коробки».

## Ключевые принципы

1. **Core — чистая логика и состояние (TypeScript)**  
   Вся логика раскладки, операций и состояния живёт в `src/core`. Никакого DOM и Angular-зависимостей в core. Базовый интерфейс реализуется в Angular-части.

2. **Иммутабельность**  
   Все операции возвращают новый state. Старый state не мутируется.

3. **Сериализуемое состояние**  
   Весь layout (включая десктопы) можно превратить в JSON и восстановить без потерь.

4. **Минимальные зависимости в core**  
   Core — zero dependencies.

5. **Начинаем как Angular-проект**  
   Всё живёт внутри одного Angular-приложения/workspace. Вынос core или обёрток в отдельные пакеты — позже.

## Модель данных

```ts
type TileId = string;
type ColumnId = string;
type DesktopId = string;

interface Tile {
  id: TileId;
  componentId: string;     // идентификатор Angular-компонента для рендера
  height?: number;         // относительная высота внутри колонки
  props?: Record<string, unknown>;
  minHeight?: number;
}

interface Column {
  id: ColumnId;
  width: number;           // относительная ширина
  tiles: Tile[];
  minWidth?: number;
}

interface Desktop {
  id: DesktopId;
  name: string;            // отображаемое имя / номер
  columns: Column[];
  focused?: {
    columnId: ColumnId;
    tileId: TileId;
  };
}

interface LayoutState {
  desktops: Desktop[];
  activeDesktopId: DesktopId;
}
```

## Основные операции ядра (LayoutEngine)

Все методы иммутабельны и возвращают новый `LayoutState`.

### Десктопы
- `createDesktop(state, name?): LayoutState`
- `renameDesktop(state, desktopId, name): LayoutState`
- `switchDesktop(state, desktopId): LayoutState`
- `closeDesktop(state, desktopId): LayoutState`

### Тайлы и колонки (внутри активного или указанного десктопа)
- `openTile(state, componentId, options?): LayoutState`
- `closeTile(state, tileId): LayoutState`
- `moveTile(state, tileId, target): LayoutState`
- `resizeColumn(state, columnId, width): LayoutState`
- `resizeTile(state, tileId, height): LayoutState`
- `focus(state, columnId, tileId): LayoutState`
- `toJSON(state): unknown`
- `fromJSON(data): LayoutState`

### Разделение ответственности

- **core/** — только типы, иммутабельные операции, сериализация. Никакого Angular.
- **Angular-часть** — рендер, сервисы, динамические компоненты, pointer events для drag/resize, привязка к шаблонам.

## Поведение по умолчанию

- Есть как минимум один десктоп.
- Новый тайл открывается в текущей focused колонке активного десктопа (снизу) или создаёт новую колонку.
- При закрытии последнего тайла в колонке — колонка удаляется.
- Горизонтальный скролл внутри десктопа.
- Вертикальный переключатель десктопов (нумерованные/именованные).

## Нефункциональные требования

- Строгий TypeScript (`strict: true`)
- Unit-тесты на core (все операции и edge-cases)
- JSDoc на публичный API core
- Нулевые внешние зависимости в `core`
- Состояние полностью сериализуемо

## Этапы разработки

1. Типы + скелет `LayoutEngine` (с поддержкой десктопов)
2. Реализация операций + unit-тесты
3. Сериализация
4. Angular-сервис-обёртка
5. Базовый рендер: переключатель десктопов + горизонтальный контейнер колонок
6. Интерактив (создание/удаление/перемещение тайлов и десктопов)
7. Resize + drag-and-drop
